# 07 - Submission checklist (tick every line before submitting)

## Venue choice (ONE venue at a time)
- [ ] Only one journal/conference holds the manuscript at any moment. The previous double submission (Applied Sciences received it 29 Aug; IEEE Access rejected it 8 Sep) overlapped, which IEEE prohibits and most journals dislike.
- [ ] The IEEE Access decision on the *old* manuscript is final. A resubmission there would need to be a substantially different paper, and it is safer to choose another venue.
- [ ] Scope fit checked on the venue's own "aims and scope" page. This is an engineering/performance study, not a cybersecurity or malware paper. Look at: software-engineering and performance venues (ICPE, ICSA, industry tracks), applied-computing journals, or journals covering ML systems / financial technology. Check current deadlines, formats, page limits and fees yourself.
- [ ] Consider posting a preprint (arXiv or similar) only if the target venue allows preprints. Check its policy first.
- [ ] Read 3-4 recent papers from the target venue and match their depth and style.

## Manuscript hygiene
- [ ] Publisher template applied fully. No "xxxx", "Doi Number", "VOLUME XX, 2017", page number "8" on every page.
- [ ] Title, abstract and conclusion contain only claims supported by `results/tables/`.
- [ ] Every number in the text matches a file in `results/`. Every figure is generated by the scripts.
- [ ] Ratio of imbalance and dataset counts recomputed from the data (old paper's "28.4:1" did not match its own counts).
- [ ] No unverified industry thresholds (latency budgets, loss statistics) without a source.
- [ ] Reference audit (05) complete; `references.bib` checked entry by entry against DOIs.
- [ ] Related work includes recent papers, not only 2002-2011.
- [ ] Limitations section states: single machine, closed-loop, no concurrency, Smile/scikit-learn parameters approximate, synthetic dataset, one dataset.
- [ ] Proofread for English; run it past a supervisor or colleague.

## Ethics, transparency, reproducibility
- [ ] **AI-use disclosure:** name the tool(s) and what they were used for (e.g., "Claude (Anthropic) was used to help draft benchmark code scaffolding, documentation and to review the manuscript; the author ran all experiments, verified all results and references, and takes full responsibility for the content"). Follow the target venue's exact policy and wording. Do not claim "all code is entirely the author's own" if it is not true.
- [ ] Dataset citation (Jesus et al. 2022) and license statement (CC BY-NC-SA 4.0 as listed on Kaggle; re-check on submission day).
- [ ] Code and raw latency files archived: GitHub repository + tagged release + Zenodo DOI. Put the DOI in the paper and in `CITATION.cff`. Do **not** upload the BAF data itself.
- [ ] Software versions table (OS, CPU, RAM, Python, JDK, Maven, Smile, scikit-learn, ONNX Runtime, waitress, requests).
- [ ] Statement that results are single-machine and may differ elsewhere.
- [ ] Author names/affiliations/emails correct; funding statement; conflict-of-interest statement; acknowledgments (supervisors, lab) as appropriate. If the work is thesis work, say so and check the venue's policy on thesis overlap.

## Cover letter (short)
- [ ] One paragraph: problem, what is new (the decomposition and identical-model comparison), main finding with numbers, why it fits this venue.
- [ ] Disclose prior versions honestly: an earlier version of this work was rejected at other venues without review; this manuscript is substantially redesigned (new dataset split, new baselines, new statistics). Follow each venue's rules on disclosure of prior submissions.
- [ ] Suggest reviewers only if the venue asks; none with conflicts.

## Final technical check
- [ ] PDF renders, figures readable in grayscale, tables not cut, fonts embedded.
- [ ] Supplementary material (if allowed): `results/tables/*.csv`, README, config.
